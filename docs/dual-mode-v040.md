# v0.4.0｜订单与颜色出口对比版

## 从哪里进入

原订单玩法完整保留，主模式尚未决定。

1. 正在玩时点右上暂停，再点“切换模式·保留进度”。恢复页也可点“返回模式选择”。
2. 菜单分别进入“订单模式”和“颜色出口”；切换需要确认，取消不会写入存档。
3. 每个模式有自己的当前局。颜色出口首次进入先看入口/出口图解，再点“开始试玩”。
4. “新开一局”只替换按钮所写的模式；订单每日挑战仍只使用订单模式的存档槽。

更新：完整解压新ZIP，关闭旧预览命令窗口，在新目录运行 start-preview.cmd。沿用同一浏览器和 http://127.0.0.1:4173/ 可以继续旧订单档；不要清浏览器存储。浏览器本地文件模式的存储行为可能不同，仍优先HTTP启动。游戏离线，无登录、数据上传或付费。

## 两种玩法

### 订单

看上方的当前订单。相同图标的货箱上下左右连成组，数量达到要求，并且叉车从相应门沿空格能到组旁，就会整组出货。每次有效放置检查当时全部旧订单，刚放红色也可能完成机械订单；新刷出的订单等下一次有效放置再检查。

保留5班、升级、特殊货件、每日与加班。v1/v2旧局继续按原规则，普通新局仍用v3。本次同时修复了取货朝向、装载/原路倒车/离场动画，以及订单、教学、暂停帮助说明。

### 颜色出口（试验）

- 北边食品出口，东边化工出口，西边机械出口；每边只有一个门，货类不变化。
- 南边只有叉车入口，不是出货口。入口格有货就无法发车。
- 同图标上下左右连成至少4件，并连到对应同色出口的门边格。
- 还要有从南入口沿空格到货组旁的路。
- 叉车到旁边启动装卸，箱子逐个沿已相连的货线出门，叉车空载返回南入口。不是把整组当硬物推过狭路。
- 目标累计30批；一次操作的连锁会完整结算，所以最后可能到31/32批。每6批只推进Shape难度档，不改变固定出口。
- 每件10分；候选全放不下时失败。本批不带升级、特殊货件、每日或加班，以免干扰核心玩法比较。

4件、30批、分值与生成权重都是明确未平衡的P0基线。没有增加暗中救场、惩罚、冷却或随机重抽。

## 进度和成绩保护

两套run有独立主档/备份/临时槽。切换、新局、取消、备份恢复、写入失败都做了回归；读取失败不会被误当作空档。损坏原文先保护再恢复。某槽待恢复时，可以返回菜单继续另一模式。

长期设置与纯外观共享；颜色出口的局数、批数、最高分和结算标记单独记录，不写订单排行榜、每日记录或订单成就。重置长期记录保留两套run；无法读取某套进度或旧终局尚无稳定身份时先阻止重置，避免旧结算以后重复记账。

## 已发现的玩法风险

专门测了用户担心的“贴出口供货”：连续seed1–100，每个seed运行贴口优先和保留空路两种固定启发式，共200局，11.44秒，双方各100次完成目标。未把10局估时pilot混入统计。

| 指标 | 贴口优先 | 保留空路 |
| --- | ---: | ---: |
| 对应出口邻近落子 | 100% | 90.43% |
| 单个新货件落下立即独立出货，占落子 | 12.91% | 19.37% |
| 这类出货占全部出货批次 | 23.53% | 33.27% |
| 峰值占用中位 | 11/49格 | 10/49格 |
| 首批出货步数中位 | 4 | 2 |
| 自然连锁 | 全部1 | 全部1 |

10,620次命令/保存恢复/逐步Replay与独立事件审计一致，0程序异常、0cap。风险是两种简单策略都能低占用持续贴口供货，4件门槛没有根除这个循环。并没有据此擅自改规则。

100对seed实际都出现了后续补货差异，所以这不是同货源的公平比赛，也不能直接与旧100,002局协议的胜率比较。机器人数据不证明哪种更好玩。

## 建议这次试玩只观察

1. 不看额外解释，能否知道该凑哪种货、为什么未出货？
2. 颜色出口是否很快变成重复贴门，而订单玩法是否仍显得绕？
3. 逐箱货线与叉车空路能否看清？原模式叉车到点和运出是否自然？
4. 更愿意重开哪一种？先记录感受，不急着指定主模式。
