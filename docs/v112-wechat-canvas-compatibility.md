# v1.0.12 微信画布兼容修复

## 范围与诊断

本轮只修复 v1.0.11 静态仓库缓存的移动微信合成兼容问题。用户报告浏览器与开发者工具正常，但手机扫码进入即持续黑屏；v1.0.10 手机可运行。

v1.0.11 的 `drawCachedWarehouse` 将 `globalCompositeOperation` 设为 `copy`，并以属性回读相等当作成功证据。腾讯官方小游戏类型文档说明 Android/iOS 不支持 `copy` 和 `lighter`；不支持的模式可能不抛异常。一个接受赋值及回读、但静默跳过 copy blit 的宿主模拟中，旧缓存返回成功，原绘制回退不执行，目标像素为空。这确认了独立兼容缺陷，也符合首帧黑屏路径，但不能证明它是实体手机黑屏或闪退的唯一原因。

来源：https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts#L6500-L6515 。构建原有参考快照为 `ad99e35a0200d4548cd879aa218ce845fd1e9fa2`；未改变参考基线。

## 最小修复

- 缓存内容仍是同一原生分辨率下的整帧底色、原逻辑 clearRect 与静态 drawWarehouse；不增加背景范围，不补画原透明区域。
- 目标画布先在单位变换下完整 clearRect，再以已验证的 `source-over` 将缓存按原生像素 1:1 回填。不能直接在未清除的背景上叠加，否则半透明边缘和分数像素会变化。
- blit 抛错后，在保存状态内重建原平台底色与逻辑 clearRect；随后恢复变换/样式、释放缓存，交回原始 drawWarehouse。失败能力仍停止逐帧重试，原生命周期失效可恢复尝试。
- 原缓存预算、释放策略、资源/主题/视口失效与原始回退保留；不进行未证实的内存或启动路径重写。
- 两处独立门禁都拒绝 `copy` 和 `lighter`。复用既有锁定 TypeScript 解析器识别真实属性赋值，包含点号、静态方括号和无插值模板字面量；注释、普通字符串及 copyright 不误报。新增测试实际注入源码并运行 preflight/build，不只匹配门禁源码。该静态门禁不求值动态表达式、别名或运行时生成的模式。
- 玩法、触控投影、预演缓存、商店、存档、字号、布局、运行美术与音频未修改。

## 真机验收仍未完成

修复后的微信工程须由开发者使用原 AppID 导入、上传测试并手机扫码，确认能进入、旧存档可继续、拖拽落点/显示正常，以及切后台再回来不黑屏。宿主模拟、桌面原生 Canvas 像素比对和构建门禁不能替代开发者工具或 Android/iOS 实际运行；未提供手机 FPS、温升或内存稳定性结论。若新包仍黑屏，应收集机型、系统/微信版本与首个真机错误日志，再定位下一问题。
