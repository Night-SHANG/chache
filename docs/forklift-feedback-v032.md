# v0.3.2｜叉车运输与玩法提示修复

2026-10-06。来自用户对 v0.3.1 的三张实测截图与“仍没有搞懂玩法”的反馈。

## 先把玩法讲清楚

你管理的是一个仓库。每次从下方挑一件货物放入棋盘，让它完成上方订单，同时别把通路和放货空间堵死。

- 订单指定货类和最低件数。相同图标的箱子上下左右相邻才算一组；不是把全棋盘同颜色相加。
- 该组达到订单要求，还要从相应出货口沿空格走到货组旁边，才能整组出货。托盘、侧门等升级仍按原规则例外执行。
- 每次有效放置后检查当时已有的所有订单，出什么货不由刚放的货物颜色决定。
- 本次旧订单全部结算后才生成新订单。新订单即使已经够数，也等下一次有效放置再检查；如果这一步堵路，仍不会出货。
- 当前没有对应货类订单时，货物留在仓库备货，不会仅因数量多自动消失。
- 标准与每日：每班6单，共5班。候选货件全都没有合法落点时失败。加班则继续接单追分，可主动结束。

## 已定位并修复

- 叉车贴图本身朝+x，行驶向量正确；错误来自到取货点后仍沿用最后一段行驶方向。只有1格的路线更恒定朝右。现在独立朝向真正相邻的货格，稳定选择最小格序号，不用可能斜向或隔墙的组中心。
- 原装载只有160ms，全部货箱直飞订单门并缩到6%，叉车不返回。现在是100ms点亮、260ms驶入、140ms装载、360ms载货倒车、140ms离场，共1000ms。箱子收拢到叉齿，变成同货类托盘与件数；沿原路倒车，载荷始终位于叉齿前。
- 侧门从实际使用的西南入口退出，不跨棋盘飞向名义订单门。计分仍归原订单。
- 门框外的车、货、尘粒被仓库边界遮住，不压住订单栏和候选栏；北门出货分数与提示不会重叠。
- 出货期间门的颜色保持正在搬运的货类，直到下一订单真正显示，避免提前变色误导。
- 订单栏分别显示“已满足·落子后检查”“松手后预计出库”“入口被堵/没有空路”等；无对应订单的库存给出备货说明。
- 三步教学补上订单要求、同图标邻接、机械堵住食品路线的原因。暂停页优先解释基础玩法，再列特殊货件；标准、每日、教学、加班各用正确目标。

## 保持兼容的边界

Domain、规则v1/v2/v3、RNG、保存格式与Replay代码的文件字节均未改变。先完成规则并保存，再播放动画；暂停、后台、设置或恢复只取消表现，不重新计算。普通单次动画多350ms，最多4单连锁约4秒，属于可调表现配置，仍需人测节奏。简化动效仍为80ms静态反馈，关闭移动/旋转/粒子。
