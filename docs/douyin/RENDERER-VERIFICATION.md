# 抖音 Canvas 兼容验证

2026-10-14，北京时间。本报告是 Node / @napi-rs/canvas 的契约及像素验证，不是抖音开发者工具或 Android / iOS 真机验收。

## 隔离边界

原浏览器、微信、Android 的 presentation 源码没有修改。抖音构建独立启用插件，固定十个原 presentation 输入的 SHA-256，所有字符串替换精确计数，源代码漂移或残留不支持 API 会直接拒绝构建。规则、经济、账户、游戏状态不经过该插件改写。

## 绘制策略

- 警示条、留空格斜纹使用有限多边形；边界内缩 1/32 逻辑像素防止浮点栅格边缘外溢。
- 7/8/9 棋盘冷态细节的保守边界在 120 单元的 [5.25,114.75]，保持原内缩范围后移除冗余 clip。
- 按压反馈直接画原圆角二次曲线及其顶部带状子路径，底部高光在边界内。
- 九套热背景 PNG 使用等比例源区域裁切，直接画到主画布；两组有限宽度测试逐像素一致，每次恰好一个原图片 drawImage，无 scratch 分配或合成。
- 复杂冷背景、商店组合预览和旋转运输共用唯一惰性 1205×1920 逻辑像素 scratch。RGBA 理论像素存储为 9,254,400 B（约 8.83 MiB），不含宿主/GPU额外拷贝。
- 没有 DPR 倍增、运行时背景缓存、每次 clip 分配、反复 resize、整帧中转或不支持的合成模式。注册工厂时零分配，主画布先创建。
- 普通热背景、棋盘、HUD 与普通精灵保持直接绘制；完全位于门口裁界内的运输货物也直接画，只有跨界部分使用局部 scratch。
- 嵌套绘制在清理前明确拒绝，具体调用点使用未裁切的内部背景函数，避免互相覆盖。每次仅清理下一次取样区及一个边缘像素，缩小/放大/复用无残影。
- 9×9 小数裁界采用整数 scratch 原点及相应源偏移，消除可避免的二次亚像素采样；极限尺寸不扩容。缩放后的主画布仍可能有边缘重采样差异，不声称所有设备逐像素相同。

## 专项结果

命令：`node --test tests/douyin-renderer*.test.ts`。

13 项通过，0 失败；对应 TypeScript no-emit 与 ESLint 通过。覆盖：斜纹、7/8/9 冷棋盘、嵌套预览、留空标记、圆角按压、九套冷背景、十八次真实热图片裁切、源指纹漂移拒绝、完整 renderer 禁用 API 扫描、66 帧运输（入库/出库 × 北/东/西 × 11 进度点）。序列化游戏及动画状态保持不变。

原型另覆盖 surface 创建数、尺寸赋值数、重入拒绝与恢复、过绘后复用、小数像素相位、主画布变换与状态恢复、最大尺寸。

全仓实际退出码和测试总数以统一验收记录为准；既有两项缺美术母图 ENOENT 不会被忽略或删除。

## 像素限制

平均差是 [0,255] 的逐 RGBA 通道数值，不是感知质量评分；很小的平均值也可能含局部边缘较大差异。

- 原点修复后，记录的 1× 出库样本平均差约 0.000009–0.000116 / 255。
- 1× 冷套装预览平均差约 0.00309 / 255；0.5× 预览平均差约 0.528 / 255、局部最大差 159，来自固定逻辑画布缩放后的边缘取样。
- 图片及字体本体、结构与遮挡保留，但不能把上述模拟结果称为抖音真机画质、内存、FPS或温升验收。
