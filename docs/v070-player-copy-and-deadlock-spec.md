# v0.7 玩家界面精简与保守死局判定

2026-10-06。依据用户v0.6实测反馈，规则方案经独立证明后批准。原入库规则不变，出库只新增一个可证明不可恢复的结束条件，不做全局解谜求解、不救场重抽、不改四档概率。

## 玩家界面

- 主菜单只入库、出库、设置。旧7×7目录入口移除，但不删除旧文件；已有中断局仍可走单一恢复流程。
- 出库难度只简单/中等/困难/专业与最高分；不展示纯混百分比、seed、对比/实验、版本、技术免责声明。
- “本地每日挑战”改“每日挑战”，保留既有每日固定种子和北京时间日界逻辑；时区/离线口径放文档，不暗示联网排行。
- 对局常驻只必要目标/进度/得分/空位、货物类型和当前原因。删除重复规则、每步叮嘱与普通保存成功状态；无声隐形调试热区也关闭。
- 保留短而有用的反馈：还差N件、未连出口、无空路、出货/连锁、双色剩余货件、入口堵塞、保存失败。不能为了短而隐去失败/丢进度的后果。
- 帮助一个入口，三句加图，玩家主动打开。初次必要操作教程保留已有实际交互，可跳过；不把静态规则说明误称互动教程。
- 诊断与复现数据保留文档/显式开发构建开关，普通构建默认无入口。

依据：Microsoft Xbox XAG109（按需上下文提示，视觉可补文字）https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109 、XAG114（清楚上下文与简单用词）https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/114 。互动教学参考 https://gameaccessibilityguidelines.com/include-interactive-tutorials/ 。链接只在项目说明，不塞进游戏UI。

## 新出库规则v8

薄封装复用冻结v6的81格、固定三门/南入口、八形66种双色图样、六次抽签、20/30/40/50概率、旧连锁和计分。只新增：一次合法落子完整结算、胜利检查与补件约定之后，如果南入口(4,8)，index76仍有货，本局失败。

证明：所有出货的空路BFS都首先要求同一个南入口为空；货物唯一删除方式是成功出货；合法放置只能往空格加货。入口被占时下一步不能删任何货，入口持续被占。归纳可知任何后续放置都不能恢复。因此提前结束只省去注定无效的填格。

直接读棋盘入口格，不以orderStatus.reason推断；状态可能先显示数量不足而漏报入口条件。完整结算后再判且已胜优先。不改旧v6，旧局恢复不静默升级/重新判输。

明确反例不能判死：入口为空但被四周围住，货组后续连接出口可从入口原地接货；当前三个出口都不可出，后续补一件可清障连锁；某组暂未接出口。入库普通/每日/无限有多门、侧门、托盘和特殊清障，不套用该判定。

新身份rulesetVersion8、runConfigId=run.outbound9_v8.<difficulty>，仍boardSize9/difficultyId。终局沿用failed/endReasonblocked；玩家失败原因依据v8终局的入口占用显示“入口堵塞”，否则“仓库放不下了”。不在load旧档时修改phase或checksum。

v8四个新存档与成绩命名空间，旧v1–v7解码和指纹不动。普通新局选v8；旧v6/v4/v5只有原中断恢复，不提供新开旧规则的UI入口。重开旧局先按现有确认流程结束，再选新档。

## 验收

TDD：入口占用有大量空位也立刻终局，完成结算后才判、胜利优先、不重复事件；所有可救反例/入库侧门特殊清障；旧引擎指纹不动。v8保存/恢复/重开/退出/14槽隔离、独立成绩和终局不可继续落子。

普通构建主界面快照不得出现seed、百分比、实验/开发/版本、北京时区或旧档目录；有效的提示与数据损失说明仍存在。显式开发构建可打开原诊断，默认点击旧热区无效。

实际game.js三尺寸检查精简画面、真实有效落子堵入口自动结束、清路连锁不误杀、重开/恢复/取消。完整lint/typecheck/tests/preflight/build/独立审查、轻量ZIP同Library身份替换、稳定Git及完整源码备份。旧400局不声称覆盖新终局规则；可读旧输入做有界前缀比对，另标验证性质。
